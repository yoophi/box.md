# 문서 카드 캔버스 (gh-65)

기존 문서 카드 보기를 페이지 단위 그리드에서 공간 캔버스로 확장한다. 구현은 캔버스 인터랙션(gh-85), 두 카드의 명시적 연결(gh-86), 편집 모달과 CAS 저장(gh-87), 통합 감사(gh-88) 순서로 진행한다. 상위 기능 gh-65는 마지막 감사 작업에 의존한다.

## 캔버스 좌표와 인터랙션 (gh-85)

카드 위치는 월드 좌표로, 화면 이동과 확대율은 카메라로 관리한다. 화면에 표시할 때만 `translate(camera) scale(camera.scale)` 변환을 적용한다. 이 구분으로 확대 상태에서 카드 drag 거리를 `화면 이동량 / 확대율`로 환산하며, 포인터 아래의 월드 좌표가 바뀌지 않도록 확대 중심을 계산한다.

카드는 문서 목록 순서를 바탕으로 결정적인 초기 위치를 얻는다. 각 카드에는 frontmatter의 `permalink`를 문서 ID로 표시하고, permalink를 아직 읽지 못했거나 없는 문서는 파일 경로를 임시 식별자로 사용한다. 작업 디렉터리가 바뀌면 카메라와 위치를 새 문서 집합으로 초기화하며 이전 디렉터리의 늦은 metadata 응답은 적용하지 않는다.

빈 캔버스를 pointer drag하면 양방향으로 pan한다. 카드 drag는 확대율을 반영해 월드 좌표를 바꾸고, 4px를 넘긴 drag 뒤 발생하는 click을 한 번 억제해 문서가 의도치 않게 열리지 않게 한다. 트랙패드 스크롤은 pan, `Control` 또는 `Command`가 포함된 wheel은 포인터 중심 zoom으로 처리한다. 명시적 축소·확대·중앙 이동 버튼과 현재 확대율을 함께 표시한다. 확대 범위는 45%부터 180%까지다.

좌표 함수는 React UI와 분리했다. 초기 배치, pan, 확대율을 반영한 drag, 포인터 고정 zoom, 확대 범위를 단위 테스트한다. HomePage 테스트에서는 실제 카드 화면에서 pan 변환, 115% 확대, 확대 상태의 카드 drag와 drag 직후 열기 억제를 확인한다.

검증 결과는 desktop 전체 13개 파일·107개 테스트, TypeScript 검사와 production build 통과다.

## 두 카드의 명시적 연결 (gh-86)

카드 한 번 클릭은 선택 상태를 전환하고, 두 번 클릭은 기존 문서 열기 동작을 유지한다. drag가 4px를 넘으면 뒤따르는 click을 억제하므로 위치 이동이 선택이나 열기로 해석되지 않는다. 선택은 최대 두 장이며 세 번째 카드를 누르면 먼저 선택한 카드를 교체한다. 선택된 카드는 테두리와 focus ring으로 표시하고 연결 도구에 선택 수를 노출한다.

두 카드 모두 서로 다른 저장된 permalink를 가져야 연결할 수 있다. 연결 동작은 기존 gh-19 API로 두 파일 이름에서 연결 엔티티를 만든 뒤 두 permalink membership을 추가한다. 같은 이름의 엔티티가 이미 있으면 번호를 붙여 이름 충돌을 피한다. 두 문서가 이미 하나의 엔티티를 공유하면 새 엔티티를 만들지 않고 공유 연결 이름을 표시한다. 같은 permalink, permalink 누락, 저장소 로딩 실패도 쓰기 전에 차단한다.

연결 snapshot의 membership을 permalink와 카드 경로에 대응시켜 같은 엔티티를 공유하는 카드 사이에 선을 그린다. 두 문서를 연결한 직후뿐 아니라 명시적 새로고침과 `connectionsChanged` 이벤트 뒤에도 저장소 snapshot을 다시 읽어 선을 복원한다. root 전환은 진행 중인 연결 결과와 이전 snapshot을 무효화한다. 카드 연결 과정은 문서 저장 API를 호출하거나 본문 wikilink를 변경하지 않는다.

## 더블클릭 문서 모달과 저장 (gh-87)

카드 더블클릭은 캔버스를 유지한 채 문서 모달을 연다. 모달은 기존 `open_document`로 원본과 revision을 읽고 공용 `MarkdownEditor`를 읽기 모드로 표시한다. 사용자가 편집으로 전환한 경우에만 draft를 바꿀 수 있다. 저장은 별도 카드 저장소 없이 기존 `save_document(path, content, expectedRevision)`를 호출하므로 frontmatter, 문서 이력과 revision CAS 계약을 그대로 따른다.

저장 성공 뒤 새 revision과 서버가 반환한 내용을 baseline으로 삼고 카드 summary를 다시 읽는다. revision 충돌과 다른 저장 오류는 모달 안에 표시하며 draft를 유지한다. 미저장 draft가 있으면 닫기나 배경 클릭이 확인 대화상자를 열고, 사용자가 명시적으로 버리기 전까지 모달과 draft를 보존한다.

각 문서 읽기와 저장에는 순번을 부여해 이전 문서의 늦은 응답을 무시한다. 모달을 연 작업 디렉터리가 바뀌면 진행 중 요청을 무효화한다. 깨끗한 모달은 닫고, 미저장 draft가 있으면 내용을 유지하면서 저장을 차단하고 변경된 root를 안내한다. 테스트는 늦은 읽기 응답, root 변경 draft 보존, 정상 CAS 저장과 이력 생성, 충돌 표시, 닫기 취소와 명시적 버리기를 검증한다.
